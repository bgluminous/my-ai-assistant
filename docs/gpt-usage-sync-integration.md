# GPT 用量同步联调结果

验证日期：2026-10-12。客户端候选版本 1.3.0，服务端候选版本 2.3.0，协议 v1。
实际运行 1 项端到端 Rust 测试，覆盖下表 12 组场景，全部通过，耗时约 411 秒。
本次未发现需要修改客户端或服务端业务代码的兼容性问题。

## 环境与范围

- 客户端：MAA 的实际采集、SQLite 存档、HTTP 传输、同步状态机及谱系聚合代码。
  使用独立本地数据库和设备身份模拟多台机器，不扫描真实 GPT 日志。
- 服务端：xil-information-service 的实际同步／管理路由、Service 和 MySQL mapper。
  非同步业务依赖沿用服务端测试替身，不读取生产配置。
- 数据库：真实 MySQL 8.0.45，通过开发连接在 `dev` 库创建随机前缀表。
- 网络：本机 HTTPS 反向代理，地址带 `/maa` 前缀，转发至实际 HTTP 服务。
  使用临时 CA 与服务器证书，只在本测试客户端内增加信任；未关闭证书验证，
  未向系统安装证书。

## 结果

| 场景 | 实际断言 | 结果 |
| --- | --- | --- |
| HTTPS 与空客户端 | 未信任 CA 时连接失败；信任后成功；握手不登记设备，空同步登记并下载 | 通过 |
| 复制、分叉与祖先晚到 | 两端复制日志不增量计数；祖先到达后修正时间，先去重再按日期／设备筛选 | 通过 |
| 全量与上传重试 | 503 条新增用量分批上传；服务端已提交但响应丢失时，重试不新增重复来源 | 通过 |
| 分页中断续传 | 第二页响应中断；重开 SQLite、重建服务端 HTTP 实例后继续原游标下载 | 通过 |
| 固定下载上界 | 翻页期间另一设备新增记录，本轮不混入，下一轮增量取得 | 通过 |
| 设备与历史保留 | 改名可见；按设备清理缓存后恢复；删除 Codex 原日志后历史仍在 | 通过 |
| 账户启停与换钥 | 停用返回 403；启用后可恢复；旧钥 401，新钥保留空间、epoch、记录及来源 | 通过 |
| 账户隔离 | 切换账户不显示旧缓存；只上传本机采集记录，不转传另一设备的下载记录 | 通过 |
| 数据代次与游标恢复 | 实际更换 epoch 及非法游标 409 后重新确认本机历史，下载结果不丢失 | 通过 |
| MySQL 写入失败 | 约束注入导致上传失败；设备与来源一同回滚，客户端保留待上传，恢复后成功 | 通过 |
| SQLite 写入失败 | 下载页写入失败时记录与游标均不提交；解除故障后重新下载成功 | 通过 |
| 管理审计 | 可查数量和结果，不含同步密钥、模拟对话正文、原始路径或 GPT 凭据 | 通过 |

## 清理与边界

测试结束已删除本轮随机前缀表，并查询确认无残留；HTTP／HTTPS 监听均已关闭，
临时证书、模拟日志和 SQLite 文件均已移除。没有修改生产配置或真实用户数据。

本次验证使用多个独立客户端存档，未启动完整 Tauri 桌面应用，
未验收窗口／托盘渲染，也未连接正式域名和部署网关。
服务端重建指 HTTP 监听及应用实例重建，不代表完整部署进程的重启验收。

复现入口、依赖和隔离要求见[专项测试说明](../scripts/codex-sync-tests/README.md#实际服务端联调)。
普通 Rust 测试默认忽略该用例；必须由联调启动器显式提供开发数据库和临时服务。
